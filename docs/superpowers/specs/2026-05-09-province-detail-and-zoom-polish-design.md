# 2026-05-09 台湾边界、省级镜头与省级侧栏修复设计

## 状态
- 已完成设计确认
- 范围聚焦于三个问题：
  - 台湾省级边界的专用数据接入
  - 进入省份后的镜头手感继续放大
  - 省级侧栏只剩把手、不显示面板与内容的问题

## 背景
- 当前全国层正式省界已经切到项目内预处理产物，hover 交互也已收敛为“纯地图 hover”。
- 但进入省级后仍存在三个明显问题：
  - 台湾的省级下钻边界不能沿用普通省份的通用 URL 规则。
  - 当前省级镜头虽然已按 `visualCenter + bounds` 工作，但放大力度仍偏保守，视觉上不够“贴脸”。
  - 进入省份后，右侧栏经常只剩“收起侧栏 / 展开侧栏”的把手，真正的面板内容没有稳定显示。
- 用户进一步明确了省级侧栏期望：
  - 默认使用省级概览卡
  - 概览卡中展示当前省份的城市列表
  - 配一张省会城市图片

## 目标
- 为台湾省级下钻提供独立、明确、可控的数据源，不再强行套用普通省份路径。
- 在不重写镜头模型的前提下，让进入省份的放大手感明显更近一些。
- 修复省级侧栏主体面板不显示的问题，并将省级内容升级为真正可用的概览卡。

## 非目标
- 本轮不重写全国层正式省界生成链路。
- 本轮不引入运行时搜图或第三方图片检索接口。
- 本轮不重构城市详情侧栏的信息架构。

## 方案对比
### 方案 A：小步稳改
- 台湾单独接专用 URL。
- 省份镜头在现有模型上增加可控 zoom bias。
- 侧栏先修显示，再补省级概览卡。
- 优点：风险最低，直接解决当前三个问题。
- 缺点：图片与省会信息需要一份静态映射数据。

### 方案 B：中度重构
- 在方案 A 基础上，把省级概览数据完全抽成统一 schema 模块。
- 优点：后续可扩展性更强。
- 缺点：本轮改动面偏大，不适合快速回到可用状态。

### 方案 C：仅功能补丁
- 只修台湾路径、镜头倍率和侧栏显示。
- 优点：最快。
- 缺点：无法满足用户提出的“城市列表 + 省会图片”诉求。

## 结论
- 采用 `方案 A：小步稳改`。
- 先解决可用性，再补轻量的省级内容质量。

## 设计 A：台湾边界单独接入
### 1. 专用 URL
- 台湾省级边界单独使用：
  - `https://geojson.cn/api/china/1.6.3/710000.topo.json`
- 不再让台湾走普通省份的通用下钻 URL。

### 2. 数据职责
- 全国层：
  - 台湾仍然作为 `710000` 的正式省级 feature 存在于生成产物中。
- 进入台湾省级：
  - 省级边界加载逻辑优先命中台湾专用 URL。
  - 若成功，使用该数据渲染台湾的省内边界。

### 3. 失败策略
- 如果台湾专用 URL 加载失败：
  - 不伪造城市边界
  - 地图显示“当前省份暂无可用城市边界数据”
  - 右侧栏仍照常显示台湾省级概览卡

## 设计 B：省份放大手感继续增强
### 1. 保持当前镜头模型
- 继续使用：
  - `visualCenter`
  - `bounds`
  - 整个窗口中心
- 不改成多阶段动画，也不改成扣除侧栏后的偏移中心。

### 2. 调整方式
- 在现有自动计算的 zoom 基础上增加一个可控 `zoomBias`。
- 同时提高允许的 `maxZoom` 上限。
- 对特大型或细长省份增加保护，避免放大过头。

### 3. 分组策略
- 普通省份：
  - 使用统一的正向 `zoomBias`
  - 目标是比现在明显更近
- 特殊省份：
  - 黑龙江
  - 内蒙古
  - 新疆
  - 西藏
  - 海南
  - 台湾
- 这些省份使用更保守的 bias 或上限保护，避免局部被裁切得过重。

### 4. 验收标准
- 点击普通省份后，画面明显比当前更近。
- 但不会让大面积边界直接出框。
- 台湾、海南等小范围区域进入后不会因过度放大而突兀。

## 设计 C：修复侧栏显示并升级为省级概览卡
### 1. 先修“只有把手，没有面板”
- 保留当前抽屉壳子与把手按钮。
- 但收紧侧栏主体的宽度与显隐逻辑：
  - 进入省份后，只要 `level === "province"` 且 `drawerOpen === true`，侧栏主体必须稳定位于视口内。
  - 不只依赖 `w-[var(--drawer-width)]` 这一层样式表达。
- 增加一次轻量运行态兜底：
  - 若进入省份后一帧内侧栏主体仍然不可见，则重新同步打开状态。

### 2. 省级概览卡内容结构
- 顶部：
  - 省份名
  - 一句当前状态说明
- 中部：
  - 当前省份城市列表
  - 优先展示本省已有边界数据里的城市名
- 底部：
  - 省会城市图片卡
  - 同时显示省会名称

### 3. 城市列表来源优先级
- 第一优先级：
  - 当前省份边界数据中可直接解析出的城市名
- 第二优先级：
  - 本地合并数据中该省的城市名
- 兜底：
  - 如果两条都拿不到，则明确显示“当前暂无城市列表数据”

### 4. 省会图片策略
- 不使用运行时自动搜图。
- 使用项目内静态映射数据：
  - 省份 -> 省会名
  - 省份 -> 图片 URL 或本地资源路径
- 若某省暂时没有图片：
  - 显示统一占位卡片
  - 保留省会名称与提示文案

### 5. 内容目标
- 省级概览卡保持轻量，不替代城市详情。
- 进入城市后，侧栏仍切换为现有城市详情流。

## 数据与模块边界
### 1. 台湾省级边界
- 单独由省级边界 URL 适配层处理。
- 不混入普通省份的通用路径判断。

### 2. 省级概览数据
- 新增一份轻量静态配置，至少包含：
  - 省份 adcode
  - 省会名称
  - 省会图片资源
- 该模块只服务省级概览卡，不侵入城市详情模块。

### 3. 城市列表提取
- 城市列表应通过独立 helper 提取，避免把“边界获取”和“侧栏展示”逻辑搅在一起。

## 错误处理
- 台湾专用 URL 失败：
  - 地图发出边界缺失提示
  - 省级侧栏照常显示
- 省会图片缺失：
  - 展示占位卡，不中断侧栏内容
- 城市列表缺失：
  - 显示明确空态文案，不显示伪造内容
- 侧栏显示异常：
  - 运行态兜底重同步一次打开状态

## 测试与验收
### 1. 自动化验证
- `typecheck` 必须通过
- 最近编辑文件诊断必须为空
- 增加或更新最小单测覆盖：
  - 台湾专用 URL 生成
  - 省级镜头 bias 计算
  - 省级概览卡数据映射与缺省行为

### 2. 人工验收
- 点击台湾进入省级时，优先命中台湾专用边界链路。
- 点击普通省份后，画面比当前更近。
- 进入省份后，右侧栏不再只剩把手。
- 省级概览卡稳定显示：
  - 省份名
  - 城市列表或空态
  - 省会图片或占位卡

## 实施顺序
1. 调整省级边界 URL 适配层，单独处理台湾
2. 调整省级镜头 zoom bias 与特殊省份保护
3. 修复 `Drawer` 主体显隐与宽度表达
4. 增加省级概览静态数据与省会图片映射
5. 渲染城市列表与省会卡片
6. 完成验证、提交并推送
