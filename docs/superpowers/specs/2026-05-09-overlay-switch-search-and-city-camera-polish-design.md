# 2026-05-09 顶部浮层解耦、跨省切换与城市镜头修复设计

## 状态
- 已完成设计确认
- 本轮聚焦四个交互问题：
  - 顶部搜索框展开时会把下方提示气泡一起带宽
  - 城市搜索需要支持“前缀优先，其次包含匹配”，并让匹配原因更直观
  - 在省级/城市级视图中，希望仍能 hover 邻省并直接切换省份
  - 点击城市后需要更合理的放大与居中，且必须考虑右侧抽屉占位

## 背景
- 当前顶部搜索已经接入到 `BreadCrumbOverlay.tsx`，但搜索框与说明提示仍属于同一浮层流布局，展开时会一起被拉伸。
- 当前搜索匹配只有简单包含匹配，虽然能搜到结果，但用户输入 `北` 时，期望优先出现 `北京` 这类前缀命中项。
- 当前全国层拥有完整省级 hover 跟随 tag，但进入省级或城市级后，这套省级 hover 交互被完全移除，导致切换邻省时不够直观。
- 当前城市跳转统一走 `openCityExperience(...)`，但镜头仍使用 `focusFeatureOnMap(...)` 的 `setFitView` 思路；这会让城市主体靠近页面上沿，且没有体现“右侧有抽屉，视觉中心应偏左”的要求。

## 目标
- 让顶部搜索框和下方提示气泡完全解耦，搜索展开时不再影响提示气泡宽度。
- 将搜索结果排序改为“前缀优先，其次包含匹配”，并对匹配关键词做轻量高亮。
- 在 `province` / `city` 视图中保留当前省城市层的同时，叠加一层较弱的全国省级 hover 热区，实现 hover 邻省、显示跟随 tag、点击直接切省。
- 为城市点击和搜索进入统一一套“考虑右侧抽屉偏移”的城市相机模型，避免城市主体贴近页面顶部。

## 非目标
- 本轮不重写全国层正式省界加载链路。
- 本轮不重构所有地图 overlay 为全新框架。
- 本轮不把搜索升级为在线联想接口。
- 本轮不处理省级和城市级以外的全局导航体系。

## 方案对比
### 方案 A：局部重构，复用现有搜索与地图状态链路
- 顶部搜索容器和提示气泡拆层。
- 搜索排序升级为“前缀优先 + 包含匹配兜底 + 关键词高亮”。
- 在省级/城市级叠加弱省级 hover 热区。
- 城市镜头改为定制相机而不是直接 `setFitView`。
- 优点：与现有代码结构贴合，能最小代价解决四个问题。
- 缺点：需要把“省级 hover 能力”从全国层提炼成多层级可复用逻辑。

### 方案 B：统一重做顶部与地图交互控制器
- 把搜索、提示、hover、切换、镜头都收敛到一个新的 overlay/controller 层。
- 优点：长期结构最统一。
- 缺点：改动范围过大，容易把上一轮刚稳定的搜索和城市跳转链路一起打散。

### 方案 C：补丁式调整
- 只修搜索容器布局、搜索排序和城市 `fitView` padding。
- 优点：最快。
- 缺点：跨省 hover 切换会变成一套临时拼接逻辑，后续很容易与全国层 hover 再次分叉。

## 结论
- 采用 `方案 A：局部重构，复用现有搜索与地图状态链路`。
- 保持当前 `openCityExperience(...)` 和全国层 `ProvinceHoverOverlay` 的语义不变，只把它们提升为跨层级可复用能力。

## 设计 A：顶部浮层解耦
### 1. 问题定义
- 当前 `BreadCrumbOverlay.tsx` 的搜索按钮、搜索框和说明气泡仍在一个纵向浮层容器里。
- 搜索框展开后会改变上层整体宽度，视觉上会把下方“单击右侧把手展开或收起侧栏”一起带宽，破坏提示气泡的独立性。

### 2. 布局策略
- 顶部浮层改为两层：
  - 第一层：面包屑、搜索按钮、横向展开搜索框
  - 第二层：独立说明气泡
- 第二层不参与第一层的宽度动画，只保持固定尺寸和自己的定位。
- 搜索框的横向展开只发生在搜索容器本身，不再影响提示层。

### 3. 目标
- 展开搜索时，提示气泡宽度、位置和换行行为保持不变。
- 顶部主操作区和说明区从视觉上明确分离。

## 设计 B：搜索排序与结果呈现
### 1. 匹配规则
- 用户已确认采用：
  - `前缀优先，其次包含匹配`
- 具体规则：
  - 若 `cityName` 或 `provinceName` 以前缀命中输入词，则排在前面
  - 若没有前缀命中，再补包含匹配
  - 同优先级内保留现有轻量排序策略

### 2. 命中示例
- 输入 `北`：
  - 第一优先返回 `北京`
- 输入 `海`：
  - 若没有前缀项，则允许命中 `上海`

### 3. 结果 UI
- 结果仍保持轻量，不引入分页或复杂筛选。
- 每项继续显示：
  - `城市名 / 所属省份`
- 对命中的关键词做轻量高亮，帮助用户理解“为什么搜到了这条”。

### 4. 目标
- 搜索结果更符合直觉，尤其是单字输入场景。
- 结果项既保持简洁，又具备足够的命中解释性。

## 设计 C：省级/城市级下的邻省 hover 切换
### 1. 用户确认的方向
- 在 `province` / `city` 视图下：
  - 保留当前省的城市边界层
  - 同时叠加一层较弱的全国省级 hover 热区

### 2. 交互行为
- 鼠标 hover 到邻省时：
  - 出现与全国层一致的省份跟随 tag
  - tag 文案和跟随方式保持一致
- 点击邻省时：
  - 直接切换到对应省份
  - 当前省城市层被新省份城市层替换
  - 右侧栏同步切到新省的省级概览

### 3. 视觉策略
- 这层省级热区不应抢当前省城市层的视觉主导。
- 它更像“弱交互层”而不是“正式展示层”：
  - hover 可见
  - 默认不抢眼
  - 不强化常驻边界

### 4. 架构策略
- 不再做第二套省级 hover 状态机。
- 复用现有：
  - `ProvinceLayer` 的 hover 事件语义
  - `ProvinceHoverOverlay` 的跟随 tag 表现
- 需要把全国层专用的省级 hover 能力，抽象为“多层级下都能挂载的省级热区层”。

### 5. 目标
- 用户在湖北省内时，hover 到湖南/河南仍能看到省级跟随 tag。
- 点击邻省后，切省动作保持和全国层一致的直觉体验。

## 设计 D：城市点击镜头改为抽屉感知相机
### 1. 问题定义
- 当前城市点击虽然会放大，但核心还是 `setFitView` 思路。
- `setFitView` 更适合“全对象塞进画布”，不适合“右侧有抽屉的详情态镜头”。
- 结果是：
  - 城市主体容易贴近页面顶部
  - 视觉中心没有向左偏移
  - 搜索进入城市和地图点击城市的镜头手感不够可控

### 2. 相机模型
- 新增统一的 `focusCityOnMap(...)` / `getCityCameraTarget(...)` 一类城市镜头模型。
- 城市镜头不再默认使用窗口正中，而是使用“抽屉感知后的可视中心”：
  - 视觉重心偏左
  - 大致落在可用区域的左侧三分之二附近
- 上下左右 padding 分开控制：
  - 右侧 padding 明显大于左侧
  - 顶部 padding 不能过小，避免主体顶到页面顶部

### 3. 数据输入
- 有完整 geometry 时：
  - 基于城市 bounds 计算 zoom 和 center
  - 同时纳入抽屉占位和顶部安全边距
- 只有 center 时：
  - 使用保守 zoom + 偏左 center 兜底

### 4. 统一入口
- 地图点击城市和搜索进入城市，都统一调用这套城市相机。
- `openCityExperience(...)` 继续负责状态切换，但相机部分改为复用新的城市镜头工具。

### 5. 目标
- 点击城市后，城市主体落在更自然的偏左可视区域。
- 不再出现“整个城市被顶到页面顶部”的观感。
- 搜索进入城市与地图点击城市保持一致镜头手感。

## 数据与模块边界
### 1. 顶部浮层
- `BreadCrumbOverlay.tsx`
  - 负责面包屑、搜索按钮、搜索框容器和独立说明气泡布局
- `CitySearchBox.tsx`
  - 保持搜索框与结果列表职责，不承担提示层布局

### 2. 搜索排序
- `citySearchIndex.ts`
  - 除了构建索引外，新增“前缀优先 + 包含匹配兜底”的排序逻辑
  - 输出可供 UI 层高亮的命中位置信息或命中类型

### 3. 省级热区层
- 可以基于现有 `ProvinceLayer` 抽象出一层“轻交互版省级热区”，或在 `ProvinceLayer` 增加模式参数。
- 目标是复用 hover 与 click 语义，不复制一套新的 `ProvinceHoverOverlay`。

### 4. 城市镜头
- 新增独立城市相机模块，职责类似当前省级的 `provinceCamera.ts`。
- 渲染层不再直接 `fitView` 城市 geometry，而是走统一城市相机工具。

## 错误处理
- 搜索索引加载失败：
  - 搜索框仍可展开，但结果区明确显示错误状态
- 邻省 hover 热区挂载失败：
  - 不影响当前省城市层和现有省内浏览
  - 至少保留当前省级/城市级主链路可用
- 城市 geometry 不完整：
  - 自动回退到 `center + 保守 zoom + 偏左 center`
