# 2026-05-09 直辖市边界、城市标签与顶部搜索修复设计

## 状态
- 已完成设计确认
- 本轮聚焦五个问题：
  - 直辖市进入省级后没有边界
  - 部分城市标签没有落在对应地界内
  - 省级高亮蓝色不够明显
  - 顶部需要一个可横向展开的全国城市搜索入口
  - 数据语义对齐 `geojson.cn` 中国地图数据集

## 背景
- 当前全国层正式省界、台湾专用省级边界、进入省份镜头与省级概览卡已经接通。
- 但省级视图下仍然存在三个明显的地图问题：
  - 直辖市在本地回退链路里经常无边界可显示。
  - 城市标签的锚点不稳定，部分标签漂移到地界外。
  - 当前 hover 和 selected 的蓝色覆盖不够深，视觉辨识度不足。
- 同时，顶部缺少一个全局城市搜索入口，用户希望通过一个搜索图标展开搜索框，并直接搜索全国城市。
- 用户还要求参考 `https://geojson.cn/data/atlas/china` 的数据语义：
  - 省级下钻的市级边界标准路径为 `https://geojson.cn/api/china/{六位省代码}.topo.json`
  - 直辖市的下一级行政区通常是区县，不应强制套用“城市级”假设

## 目标
- 修复直辖市在省级视图下的边界显示，保证北京、天津、上海、重庆至少能展示下一级行政边界。
- 将城市标签锚点从“行政中心点”升级为“面内视觉锚点”，减少标签漂移。
- 提升 hover 和 selected 的可见性，让蓝色覆盖层更明确。
- 增加顶部搜索图标与横向展开搜索框，支持全国城市搜索并直接进入城市详情。

## 非目标
- 本轮不重写全国层正式省界生成链路。
- 本轮不把搜索做成在线接口依赖。
- 本轮不新增独立的全局顶栏布局系统。
- 本轮不全面重构省级和城市级所有 overlay 组件。

## 方案对比
### 方案 A：按行政层级修正 + 轻量搜索接入
- 直辖市允许展示 `district` 边界。
- 城市标签改用视觉锚点。
- 高亮蓝色整体加深一档。
- 顶部搜索接入现有面包屑浮层，并直接进入城市详情。
- 优点：改动集中，能直接解决本轮五个问题。
- 缺点：需要新增一层全国城市索引和城市锚点归一化。

### 方案 B：统一省市标签与搜索框架
- 省标签、城市标签、搜索和跳转都统一成一套 overlay 与索引系统。
- 优点：长期结构最干净。
- 缺点：重构范围过大，不适合本轮快速回到稳定可用状态。

### 方案 C：止血补丁
- 只放宽直辖市过滤条件、加深颜色并补一个简单搜索框。
- 优点：最快。
- 缺点：城市标签错位问题仍会反复出现。

## 结论
- 采用 `方案 A：按行政层级修正 + 轻量搜索接入`。
- 先把语义与入口修正到合理状态，再保留未来统一框架的余地。

## 设计 A：直辖市边界与高亮颜色
### 1. 行政层级修正
- 普通省份在省级视图下继续展示 `city` 边界。
- 直辖市进入省级后，允许展示下一级 `district` 边界。
- 数据获取优先级：
  - 先读取 `geojson.cn` 省级下钻数据
  - 如果标准 `city` 结果为空，且当前省份属于直辖市，则接受 `district`
  - 若远端失败，再走本地回退链路；本地回退时同样适用这套层级判定

### 2. 直辖市范围
- 首批按固定 adcode 处理：
  - `110000` 北京
  - `120000` 天津
  - `310000` 上海
  - `500000` 重庆

### 3. 边界显示目标
- 直辖市不再因为“没有 city 级要素”而整层消失。
- 文案层面允许把“城市边界”语义调整为“下一级行政区边界”，避免展示概念错误。

### 4. 高亮颜色增强
- 在现有蓝色语义上整体加深一档，不更换色系。
- 调整点包括：
  - hover 边线更亮
  - hover 填充更深
  - selected 与 hover 的差异进一步拉开
- 目标是让覆盖层更容易一眼分辨，而不改变当前整体视觉风格。

## 设计 B：城市标签改为面内视觉锚点
### 1. 问题定义
- 当前城市标签大多直接使用 `center`，缺失时退到 bbox center。
- 对狭长、多岛、凹形区域来说，这不是稳定的视觉锚点，容易漂移到区域外。

### 2. 统一锚点优先级
- 城市标签锚点统一采用以下优先级：
  - `labelAnchor`
  - `visualCenter`
  - `centroid`
  - `center`
  - 最后才是算法兜底

### 3. 数据归一化策略
- 在远程和本地城市数据归一化阶段，优先读取源数据自带的：
  - `centroid`
  - `center`
- 同时补齐项目内 `GeoFeature.properties` 的：
  - `labelAnchor`
  - `visualCenter`
- 若源数据没有更好的落点，再计算一个尽量落在面内的视觉中心作为兜底。

### 4. 渲染策略
- 城市标签渲染不再直接读取 `center`。
- 统一读：
  - `feature.properties.labelAnchor ?? feature.properties.visualCenter ?? feature.properties.center`
- 同时补两层轻量约束：
  - 视口边缘裁剪
  - 简单碰撞过滤

### 5. 目标
- 大部分城市标签落在对应行政区主体内。
- 沿海、狭长、多面城市不再频繁出现“文字跑出地界”的观感。

## 设计 C：顶部搜索图标与全国城市搜索
### 1. 接入点
- 不新增全局顶栏组件。
- 搜索入口直接挂到现有顶部浮层：
  - `BreadCrumbOverlay.tsx`
- 形式为：
  - 顶部新增搜索图标
  - 单击后横向滑出搜索框

### 2. 搜索数据
- 搜索不依赖在线接口。
- 使用项目内本地城市索引：
  - 从现有全国省市数据中提取城市名、所属省份、行政区代码和中心点
  - 首次搜索时懒构建或懒加载

### 3. 结果动作
- 搜索结果点击后，按用户确认的行为执行：
  - 直接进入对应城市详情
  - 自动切到所属省份
  - 地图聚焦到该城市
  - 右侧栏切换到该城市详情流

### 4. 统一入口
- 新增一条统一命令式入口，例如：
  - `openCityExperience(...)`
- 负责统一执行：
  - 进入所属省份
  - 进入城市
  - 相机跳转
  - 打开右侧栏
- 搜索、地图点击和未来可能的其他跳转都复用这条链路，避免行为分叉。

### 5. 搜索交互
- 结果列表保持轻量：
  - 最多展示前 8 到 10 条
  - 每条显示 `城市名 / 所属省份`
- 支持：
  - 键盘上下选择
  - 回车进入
- 空态：
  - 无匹配时显示“未找到匹配城市”
  - 索引加载失败时显示“城市索引加载失败”

## 数据与模块边界
### 1. 直辖市层级判断
- 独立为一条轻量规则，不扩散到所有城市逻辑。
- 普通省份仍优先沿用现有 `city` 语义。

### 2. 城市锚点归一化
- 归一化模块负责把 `center/centroid` 等字段提升为统一的 `labelAnchor/visualCenter` 语义。
- 渲染层只消费统一字段，不重新猜测锚点。

### 3. 城市搜索索引
- 新增独立搜索索引模块，只负责：
  - 提供搜索条目
  - 提供模糊匹配结果
- 不承担地图渲染职责。

### 4. 城市体验入口
- 新增统一城市体验入口，负责“选中城市后的整套动作”。
- UI 层只调用入口，不各自拼接状态与镜头逻辑。

## 错误处理
- 直辖市远端数据失败：
  - 回退到本地合并数据
  - 若仍无数据，则显示“当前省份暂无下一级边界数据”
- 城市锚点缺失：
  - 使用算法兜底视觉中心
- 搜索索引失败：
  - 搜索框可展开，但明确显示错误状态
- 搜索命中后跳转失败：
  - 保留当前视图并提示“城市跳转失败，请重试”
