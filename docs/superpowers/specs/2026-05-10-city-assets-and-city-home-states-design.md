# 2026-05-10 城市资料页与城市首页状态设计

## 1. 背景

当前城市侧栏存在两个直接影响本地闭环的问题：

- 点击进入城市后，`CityHome` 在加载失败时只打印日志，没有明确错误态，用户容易感知为“侧栏什么都没有”。
- 本地附件与正文图片虽然已经能落盘，但仍然分散在单个 Trip 内，城市维度没有统一入口去“找资料、读资料”。

在当前版本只聚焦本地上传、本地阅读、本地备份闭环的前提下，本次设计不引入 R2、同步状态、多设备访问，也不重构现有存储模型。

## 2. 目标

本次设计目标：

- 让城市首页具备明确的 `loading / error / empty / ready` 四态，不再出现“像坏掉一样的空白”。
- 在城市维度新增“本地资料”入口，把该城市下的附件与正文图片聚合出来。
- 支持站内预览最关键的本地资料类型：图片、Markdown/txt、PDF。
- 继续复用当前本地落盘、`local://` 资源协议、Trip 附件与正文图片引用模型。

本次不做：

- 不纳入 R2、上云、`remote_url` 回退。
- 不引入全文搜索、标签筛选、批量操作。
- 不把城市封面、Trip 封面并入资料列表。
- 不做 DOCX、XLSX、ZIP 等复杂格式的站内解析。
- 不扩展 POI 附件模型。

## 3. 方案概览

在现有 `Drawer` 视图模型上新增一个 `city-assets` 视图，与 `city-home`、`trip-list`、`trip-detail`、`poi-detail` 并列。

城市首页增加一个新的主入口按钮 `本地资料`。用户进入后看到该城市下所有 Trip 的本地资料聚合列表，资料来源限定为：

- `trip_attachment`：Trip 附件 Tab 上传的文件
- `trip_inline_asset`：Trip 正文 Markdown 中引用的本地图片

点击资料项后，在侧栏内直接预览可支持的格式；不可预览的格式保留“系统打开”能力。

## 4. 信息架构

### 4.1 Drawer 视图

当前：

- `city-home`
- `trip-list`
- `trip-detail`
- `poi-detail`

新增：

- `city-assets`

`city-assets` 的返回行为遵循现有 `Drawer` 顶部“返回”按钮模式：

- 从 `city-home` 进入 `city-assets` 时，返回后回到 `city-home`
- 从 `city-assets` 不再继续跳转更深层级视图，避免抽屉层级继续膨胀

### 4.2 CityHome 按钮区

城市首页按钮区调整为三项：

- `查看旅行记录`
- `本地资料`
- `导出备份`

`导入备份` 与 `导出诊断` 维持现有位置，不并入主导航按钮。

## 5. 城市首页状态设计

`CityHome` 从当前的“`data === null` 就一直显示骨架屏”改为显式四态：

### 5.1 loading

用于首次进入城市、主动重试、封面更新后重新拉取数据时的短暂加载态。

表现：

- 显示现有骨架屏
- 不显示错误文案

### 5.2 error

当 `db.getCity(...)` 失败时进入错误态。

表现：

- 显示明确文案，例如“城市资料加载失败”
- 提供 `重试` 按钮
- 保持抽屉头部城市名与返回结构可见

### 5.3 empty

当城市已成功建档，但没有任何实际内容时进入空态。

判定建议：

- `tripCount === 0`
- `poiCount === 0`
- 无城市简介
- 无城市封面

空态目标不是隐藏界面，而是引导进入下一步。

表现：

- 仍显示城市标题
- 明确告知“这个城市还没有本地资料”
- 给出两个行动入口：
  - `查看旅行记录`
  - `本地资料`

### 5.4 ready

当城市已有任意可展示内容时，显示完整首页：

- 城市封面
- 城市简介
- 统计卡片
- 入口按钮
- 备份与诊断入口

## 6. 数据范围与聚合规则

### 6.1 聚合范围

城市资料页仅聚合两类资产：

- Trip 附件
- Trip 正文内嵌图片

明确排除：

- `City.cover_asset_id`
- `Trip.cover_asset_id`

原因：

- 封面更接近展示装饰资源，而不是“资料库”内容
- 混入封面会降低资料列表可读性

### 6.2 去重规则

同一个 `asset_id` 若同时出现在：

- `trip_attachment`
- `trip_inline_asset`

则只返回一条记录，避免列表重复。

来源优先级：

- 优先标记为 `attachment`
- 若只有正文引用，则标记为 `inline`

### 6.3 排序规则

城市资料页默认按最近活跃的 Trip 优先，再按资源创建时间倒序：

- `Trip.updated_at DESC`
- `Asset.created_at DESC`

同时在 UI 层按 Trip 分组展示。

## 7. 主进程与数据接口

### 7.1 新增 `db:getCityAssets(cityId)`

主进程新增城市级聚合查询接口，返回扁平化列表。

返回字段至少包含：

- `asset_id`
- `type`
- `mime`
- `original_filename`
- `local_path`
- `trip_id`
- `trip_title`
- `source_kind`：`attachment` | `inline`
- `created_at`

实现原则：

- 基于现有 `Asset`、`Tag`、`Trip` 关系聚合
- 不修改数据库 Schema
- 不引入新表

### 7.2 新增 `file:readLocalText(localPath)`

为文本类站内预览新增只读接口。

接口职责：

- 读取 `userData/assets/` 下的文本类文件
- 返回 UTF-8 文本内容供渲染层显示

安全约束：

- 只允许读取 `assets/` 目录内文件
- 复用现有路径规范化与前缀校验思路
- 限制最大读取大小，避免大文件拖垮渲染进程
- 非文本类文件直接拒绝

建议限制：

- 默认上限 1 MB

失败时返回结构化错误，前端据此显示“无法预览，可用系统打开”。

## 8. 前端视图设计

### 8.1 新增城市资料视图

新增 `CityAssets` 组件，由 `Drawer` 在 `view === "city-assets"` 时渲染。

职责：

- 拉取城市资料列表
- 维护选中项
- 呈现预览区
- 显示列表空态、加载态、错误态

### 8.2 布局

保持与当前 Trip 详情页相近的双栏思路，但更轻量：

- 左侧：资料列表
- 右侧：预览面板

若抽屉宽度较紧，可通过 CSS 保持列表列宽固定、预览区自适应。

### 8.3 列表项信息

每项显示：

- 文件名
- 类型标签
- 来源：`附件` 或 `正文图片`
- 所属 Trip 标题
- 操作按钮：`预览`、`打开`

交互规则：

- 单击列表项：选中并尝试预览
- 点击 `打开`：始终走系统默认程序

### 8.4 预览支持矩阵

支持站内预览：

- `image/*`
- `application/pdf`
- `text/markdown`
- `text/plain`

处理方式：

- 图片：直接使用 `local://` 地址渲染
- PDF：在预览区内嵌展示
- Markdown / txt：通过 `file:readLocalText` 读取后只读显示

不支持站内预览：

- `application/msword`
- `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- 压缩包
- 表格类文件
- 未识别二进制文件

不支持预览时，预览区显示说明文案与 `用系统打开` 按钮。

## 9. 错误处理

### 9.1 CityHome

- `db.getCity(...)` 失败：显示错误态与重试按钮
- 城市封面上传失败：继续使用 toast，不影响主视图状态机

### 9.2 CityAssets

- `db:getCityAssets` 失败：显示错误态与重试按钮
- `file:readLocalText` 失败：显示无法预览说明
- PDF 内嵌失败：显示降级说明并允许系统打开

### 9.3 空态

需要区分两个空态：

- 城市首页空态：城市还没有内容
- 资料页空态：城市已有内容，但暂无附件或正文图片

## 10. 测试与验收

### 10.1 手动验收

至少覆盖以下路径：

1. 进入一个全新城市，侧栏不再表现为空白故障
2. 城市首页能正确显示 loading / error / empty / ready
3. Trip 附件上传后，城市资料页能看到文件
4. Trip 正文插图后，城市资料页能看到图片
5. 图片可站内预览
6. Markdown / txt 可站内预览
7. PDF 可站内预览或明确降级
8. 不支持预览的格式可以系统打开

### 10.2 自动测试

优先补充高价值测试：

- `db:getCityAssets` 聚合与去重逻辑
- `file:readLocalText` 的路径约束与大小限制

不要求本轮为整个资料页新增大规模渲染层快照测试，以避免增加低价值维护成本。

## 11. 实施边界

本次只做“城市资料页 + 城市首页状态修复”的最小闭环，不延伸到以下议题：

- POI 附件
- 云同步
- 文件搜索
- 批量管理
- 资源重命名
- 独立资源中心首页

## 12. 预期结果

完成后，当前本地闭环会从“文件已经存进去了”提升为：

- 进入城市时有稳定、明确的首页状态
- 城市维度能找到本地资料
- 常见本地资料能直接在应用内阅读
- 复杂格式仍可通过系统程序打开

这能在不改动现有存储模型的前提下，显著提高“本地上传 + 本地阅读”的完成度。
