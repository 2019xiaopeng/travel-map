# 2026-05-08 省界精细化与全国层交互重构设计

## 状态
- 已完成设计确认
- 省界策略：`高德 API + 本地缓存`
- 首屏策略：宁可先空一瞬，也不显示粗糙省界
- hover 策略：轻高亮 + 跟随提示，移出立即消失

## 背景
- 当前全国层的本地省界轮廓过于粗糙，视觉上像手工识别后的简化边界，不适合作为正式展示。
- 直接切到高德 `DistrictSearch` 后，如果等待所有省份边界都完成再统一渲染，会导致全国层短时间无法点击进入省级。
- 现有 hover 提示由地图覆盖物事件和 `AMap.Text` 实例分散控制，生命周期不稳定，导致“鼠标放上去出现后不消失”。
- 上一轮大改已经收敛了侧边栏状态与城市级流程，本轮应聚焦全国层省界精细化与交互稳定性，不再扩散范围。

## 目标
- 全国层正式省界只展示高精度边界，不再把粗糙本地轮廓暴露给用户。
- 省界数据具备缓存能力，避免每次冷启动都完全依赖实时查询。
- hover 提示与高亮改为统一状态驱动，确保移入出现、移出即消失，不残留。
- 点击省份进入省级的主流程在精细化重构后仍然稳定可用。

## 方案对比
### 方案 A：纯高德实时查询
- 首屏直接查询 `DistrictSearch`，待结果返回后渲染省界与交互层。
- 优点：边界最精细，数据源最直接。
- 缺点：每次冷启动都依赖网络与接口速度，首屏等待更明显。

### 方案 B：高德 API + 本地缓存
- 首次从高德拉取省界，标准化后写入本地缓存。
- 后续优先读取缓存，缓存缺失或明确失效时再回源高德。
- 无缓存时首屏只显示底图与轻量加载态，不显示粗糙本地省界。
- 优点：兼顾精细化、稳定性与后续启动速度。
- 缺点：需要单独实现缓存读写、版本控制与失败降级。

### 方案 C：离线预制高精度边界包
- 在构建或预处理阶段生成高精度省界文件，运行时不再依赖 API。
- 优点：运行时最稳定、最快。
- 缺点：数据维护链路更重，且不如直接利用高德现有行政区服务自然。

## 结论
- 采用 `方案 B：高德 API + 本地缓存`。
- 本地粗糙省界退出正式渲染链路，不再作为用户可见边界。
- 全国层正式省界来源只有两种：高德真边界或其本地缓存副本。

## 设计 A：数据源与缓存架构
### 1. 正式数据源
- 新增 `provinceBoundarySource`，统一负责全国层省界的获取、标准化、缓存命中与失败降级。
- 正式渲染只接受标准化后的 `GeoFeature[]`，不再由 `ProvinceLayer` 直接决定从哪里取边界。
- 标准化结果必须至少包含：
  - `id`
  - `name`
  - `center`
  - `geometry`
  - `source`：`cache | amap`

### 2. 缓存策略
- 缓存单位为全国层整包省界数据，而不是逐省散存；这样首屏读取更简单，版本管理也更直接。
- 缓存介质优先使用本地文件或既有 Electron 本地数据目录，避免只依赖浏览器内存态。
- 缓存需包含最小元信息：
  - 数据版本
  - 写入时间
  - 来源
- 本轮不强制做复杂过期策略；先采用“有缓存就用，手动或版本变更时刷新”的稳妥方案。

### 3. 首屏行为
- 若缓存命中：
  - 直接渲染缓存省界
  - 可在后台异步刷新，不阻塞交互
- 若缓存未命中：
  - 只显示底图与轻量加载态
  - 等高德真边界整包完成后再一次性渲染
- 本地粗糙省界不再承担首屏正式展示职责

### 4. 失败降级
- 高德查询失败且缓存存在：继续使用缓存
- 高德查询失败且缓存不存在：显示明确错误提示，并保留“稍后重试”
- 不再回退到当前粗糙本地省界作为正式视觉输出

## 设计 B：全国层交互状态机
### 1. 单一状态源
- 全国层新增并统一维护以下状态：
  - `provinceBoundaryStatus`：`loading | ready | error`
  - `hoveredProvinceId`
  - `selectedProvinceId`
- `ProvinceLayer`、`ProvinceHoverOverlay`、`ProvinceTagOverlay` 都只能消费这些状态，不再各自维护隐式 hover 生命周期。

### 2. hover 行为
- `mouseenter`：设置 `hoveredProvinceId`
- `mousemove`：仅更新提示位置
- `mouseleave`：清空 `hoveredProvinceId`
- tooltip 是否可见只由 `hoveredProvinceId !== null` 决定
- 这样可以从根上消除 “提示出现后不消失” 的问题

### 3. click 行为
- 点击省份后：
  - 写入 `selectedProvinceId`
  - 进入省级
  - 触发聚焦
  - 卸载全国层 hover 提示与交互层
- 进入省级后，全国层相关 overlay 不得残留

### 4. 固定标签与 hover 提示分工
- 固定省名标签：
  - 负责识别与点击入口
  - 不负责 hover 提示生命周期
- hover 提示：
  - 只负责临时反馈
  - 不承担点击入口
- 这样可以避免一个元素同时承担“常驻显示”和“瞬时提示”两套职责

## 设计 C：组件职责重构
### 1. `provinceBoundarySource`
- 负责：
  - 读取缓存
  - 查询高德 `DistrictSearch`
  - 标准化几何
  - 处理缓存写入与错误返回
- 不负责地图绘制

### 2. `ProvinceLayer`
- 只负责绘制正式省界和点击热区
- 接收标准化后的省界数据作为输入
- 不再直接感知缓存或 API 细节

### 3. `ProvinceHoverOverlay`
- 独立负责 hover 提示展示与位置同步
- 不再把 tooltip 生命周期混在 `ProvinceLayer` 内部
- 保证进入省级或离开 hover 时立即卸载或隐藏

### 4. `ProvinceTagOverlay`
- 只负责固定省名标签的渲染与点击
- 标签密度继续按缩放和最小像素距离收敛
- 不再承担 tooltip 控制

## 设计 D：测试与验收
### 1. 自动化检查
- `typecheck` 通过
- 最近编辑文件的诊断结果为空
- 为数据源层补最小单测：
  - 缓存命中分支
  - 缓存缺失 + API 成功分支
  - 缓存缺失 + API 失败分支

### 2. 交互验收
- 无缓存时首屏不出现粗糙省界
- 缓存命中或 API 返回后，省界轮廓明显比当前本地数据更精细
- 鼠标移入省份时出现高亮与提示，移出后立即消失
- 点击省份稳定进入省级，不因边界加载策略变化而失效
- 进入省级后全国层 tooltip 与 hover 效果不残留

### 3. 风险控制
- 最大风险是高德接口响应慢导致全国层等待过长，因此需要清晰加载态和缓存优先策略
- 第二个风险是缓存格式一旦变化会影响兼容，因此需给缓存加版本字段
- 第三个风险是交互层拆分后事件绑定变复杂，因此 `ProvinceLayer` 与 `ProvinceHoverOverlay` 的职责边界必须严格

## 不在本轮范围内
- 不在本轮替换地图供应商
- 不在本轮重写省级与城市级业务内容组件
- 不在本轮引入复杂缓存失效策略或后台定时同步机制
