# 2026-05-09 省界、标签与省级镜头重构设计

## 状态
- 已完成设计确认
- 全国层正式省界来源：`geojson.cn` 的 `china.topo.json`
- 进入省级后的市区边界来源：将全国边界 URL 中的 `china` 替换为对应省份的 6 位行政区代码
- 省级镜头策略：进入省份后对齐整个窗口中心，再按该省边界范围放大

## 背景
- 当前全国层正式省界主要依赖高德 `DistrictSearch` 结果与既有缓存链路，但实际渲染中除个别省份外，很多省界并不贴合真实行政区轮廓。
- 固定省标签仍然依赖简化的几何中心与投影裁剪规则，导致黑龙江等形状特殊或跨度较大的省份标签在默认视图下不稳定，甚至只在 hover 时短暂可见。
- 进入省份时仍然主要依赖 `setFitView` 这一类通用聚焦方式，无法表达“把该省移到画面中心，再放大到刚好顶住四周”的镜头意图。
- 进入省份后的地图状态、抽屉状态、镜头移动尚未收敛成统一事务，因此会出现“已经点进省份，但右侧栏没有显示”的体验问题。

## 目标
- 全国层正式省界统一切换到一份真实、可控、可复现的省级边界数据，不再把不稳定的运行时查询结果作为正式视觉输出。
- 固定省标签在默认视图下稳定显示，尤其是黑龙江、内蒙古、新疆、西藏等特殊形状省份不再因简单裁剪逻辑而丢失。
- 点击省份后，镜头行为明确满足“先到窗口中心，再按边界范围放大”的视觉预期。
- 进入省份后右侧栏稳定显示，省级流程不再受地图事件时序影响。

## 非目标
- 本轮不替换高德底图与地图 SDK。
- 本轮不重写城市和 POI 业务内容组件。
- 本轮不要求把全国层和省级层的所有边界都统一成同一套离线打包格式，但省级城市边界的 URL 规则需统一抽象。

## 方案对比
### 方案 A：继续用高德作为全国层正式省界
- 优点：延续当前链路，改动面最小。
- 缺点：边界贴合度和稳定性已经暴露上限，无法保证全国层正式视觉质量。

### 方案 B：运行时直接解析 `china.topo.json`
- 优点：正式数据源真实且完整，运行时可以直接切换到省级真实边界。
- 缺点：首屏解析压力较大，标签锚点和镜头中心仍需临时计算，稳定性不足。

### 方案 C：以 `china.topo.json` 为源，预处理成项目内正式省级产物
- 优点：正式边界、标签锚点、镜头中心、边界范围都可提前固化，运行时只消费稳定产物。
- 缺点：需要增加一层预处理脚本与产物管理。

## 结论
- 采用 `方案 C`。
- `china.topo.json` 作为全国层正式省界的原始来源。
- 运行时全国层不再依赖高德 `DistrictSearch` 作为正式省界来源。
- 省级城市边界继续通过 `geojson.cn` 的 URL 规则按省份 6 位行政区代码拉取。

## 设计 A：正式边界数据架构
### 1. 原始数据源
- 全国层原始数据采用：`https://geojson.cn/api/china/1.6.3/china.topo.json`
- 该文件提供完整省级几何与省级元信息，包括：
  - `code`
  - `name`
  - `fullname`
  - `center`
  - `geometry`

### 2. 预处理产物
- 在项目内生成一份运行时直接消费的正式省级边界产物。
- 产物建议为单独文件，例如 `province-boundaries.generated.json`，结构至少包含：
  - `id`
  - `name`
  - `fullname`
  - `geometry`
  - `bounds`
  - `visualCenter`
  - `labelAnchor`
  - `sourceVersion`

### 3. 数据职责
- 预处理阶段负责：
  - TopoJSON 转换为普通 GeoJSON
  - 计算省级 bounds
  - 计算稳定的 `visualCenter`
  - 计算稳定的 `labelAnchor`
  - 固化特殊省份的手工修正参数
- 运行时负责：
  - 读取正式省级边界产物
  - 渲染全国层边界
  - 使用预处理元数据驱动标签、hover 和进入省级镜头

### 4. 为什么不再用运行时高德全国层边界
- 高德运行时查询更适合作为在线补充或缓存策略，而不是全国层正式展示的唯一真值。
- 用户当前对问题的核心诉求是“边界真实贴合”，这一点需要一份项目可控的稳定产物才能保证。

## 设计 B：省标签与 hover
### 1. 标签锚点
- 固定省标签不再使用简单 bbox center。
- 每个省使用预处理阶段生成的 `labelAnchor`。
- `labelAnchor` 的优先级为：
  - 数据源 `center`
  - 基于几何修正后的可视锚点
  - 特殊省份的显式覆盖值

### 2. 特殊省份策略
- 对以下省份允许单独固化锚点，以确保默认视图下标签稳定：
  - 黑龙江
  - 内蒙古
  - 新疆
  - 西藏
  - 海南
  - 台湾

### 3. 标签裁剪规则
- 不再只按“投影顺序 + 最小距离”简单剔除。
- 改为两段策略：
  - 基础必显集合：大省、边疆省、直辖市优先保留
  - 拥挤裁剪：对剩余标签做最小像素间距过滤
- 这样可以保证黑龙江等省份不会因为排序或投影偶然性而消失。

### 4. hover 分工
- 固定标签负责识别与点击入口。
- hover tooltip 只负责瞬时反馈，不负责常驻表达。
- tooltip 与固定标签的职责分离，避免 hover UI 覆盖或干扰其他操作控件。
- 进入省级后，全国层 hover 与标签层必须立即卸载。

## 设计 C：进入省份后的镜头
### 1. 镜头目标
- 点击省份后，镜头效果应满足：
  - 该省视觉主体进入整个窗口中心
  - 该省边界在放大后尽量贴近画面四周

### 2. 镜头元数据
- 每个省预处理产物中包含：
  - `bounds`：完整边界外接范围
  - `visualCenter`：该省进入时的目标视觉中心

### 3. 镜头算法
- 不再直接依赖 `setFitView` 作为最终体验。
- 新镜头逻辑改为：
  - 根据 `visualCenter` 把地图中心平移到整个窗口中心
  - 根据 `bounds` 和当前窗口尺寸计算目标 zoom
  - 目标 zoom 以“上下左右尽量贴边”为准，而不是简单留白

### 4. 特殊省份微调
- 允许为以下省份单独加镜头修正参数：
  - 黑龙江
  - 内蒙古
  - 新疆
  - 西藏
  - 海南
  - 台湾
- 这些修正参数属于正式设计的一部分，而不是临时 hack。

### 5. 接口调整
- `focusFeatureOnMap()` 不再只接收 `geometry`。
- 应升级为接收类似如下的正式输入：
  - `geometry`
  - `bounds`
  - `visualCenter`
  - `focusMode`

## 设计 D：进入省份与右侧栏联动
### 1. 单一事务
- 进入省份必须收敛为单一 action，例如 `openProvinceExperience(provinceFeature)`。
- 这个 action 一次性负责：
  - 记录 `provinceId`
  - 记录 `provinceName`
  - 设置 `level = "province"`
  - 设置 `drawerOpen = true`
  - 触发镜头移动

### 2. 地图层职责
- 地图图层只负责报告“用户点击了哪个省”。
- 地图图层不再自己分别调用 store 更新和镜头聚焦，避免状态与视觉分裂。

### 3. 抽屉显示约束
- 进入省份后右侧栏应满足两个条件：
  - `level === "province"`
  - `drawerOpen === true`
- 抽屉壳体仍然保持单一控制入口，避免多处按钮互相覆盖或打架。

### 4. 失败兜底
- 若进入省份后下一帧仍未看到抽屉挂载，应记录一次明确 warning。
- 同时触发一次强制兜底打开，避免出现“状态看似已切换，但右侧栏未显示”的沉默失败。

## 设计 E：省级城市边界数据链路
### 1. URL 规则
- 进入省份后的市区边界 URL 采用与全国边界相同的 `geojson.cn` 规则。
- 将 URL 中的 `china` 替换为该省的 6 位行政区代码即可。

### 2. 数据边界
- 全国层正式边界使用项目内预处理后的稳定产物。
- 省级城市边界使用基于 6 位行政区代码的远程数据拉取链路。
- 这样可以把全国层正式视觉质量与省级层数据加载效率解耦。

### 3. 适配职责
- 新增统一的数据源适配层，负责：
  - 生成全国层和省级层的边界 URL
  - 规范化返回字段
  - 把 `code/adcode` 统一转为项目使用的 6 位 ID

## 设计 F：测试与验收
### 1. 自动化验证
- `typecheck` 必须通过。
- 最近编辑文件诊断必须为空。
- 增加最小单测覆盖：
  - TopoJSON 预处理后省级数量与关键字段完整性
  - 特殊省份 `labelAnchor` 存在
  - 省级 URL 生成规则正确
  - 进入省份镜头参数计算结果稳定

### 2. 交互验收
- 全国层除个别特殊省份外，其余省边界也应明显贴合真实行政区轮廓。
- 黑龙江在默认全国层视图下标签稳定可见。
- hover 提示出现和消失都稳定，不覆盖主要 UI 控件。
- 点击省份后镜头明显表现为“选中该省并移到画面中心后放大”。
- 进入省份后右侧栏稳定显示，并展示省级概览内容。

### 3. 风险控制
- 最大风险是预处理产物与运行时渲染字段不一致，因此需要固定 schema。
- 第二个风险是特殊省份修正参数缺失导致标签或镜头异常，因此需要显式白名单。
- 第三个风险是进入省份 action 仍被多个组件部分接管，因此需要强制收敛到单一入口。

## 实施顺序
1. 引入 `china.topo.json` 的预处理链路，生成正式省级边界产物
2. 替换全国层边界与标签数据源
3. 重写进入省份镜头逻辑
4. 把进入省份流程收敛为单一事务，并接通右侧栏联动
5. 接入省级城市边界 URL 适配层
6. 完成自动化验证与交互验收
