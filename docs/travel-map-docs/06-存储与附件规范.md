# 06｜存储与附件规范（本机优先 + 可选 R2 同步）

> 本文定义：图片/文档等附件在本机如何落盘、如何与数据库关联、如何可选上传到 Cloudflare R2 并生成 URL，以及 zip 全量导出应包含什么。

## 1. 总体目标

- 本机优先：不依赖服务器也能完整浏览与编辑
- 可选同步：上传到 Cloudflare R2 后可通过 URL 访问（为“第二阶段完全在线/多端”铺路）
- 可备份：zip 全量导出可恢复到任意机器
- 可校验：用 hash/manifest 校验完整性，减少“丢图/丢附件”

## 2. 已确认决策

- ✅ 附件策略：**本地复制 + 可选同步**（本地为主，URL 兜底）
- ✅ 备份与迁移：导出为 **zip 全量**
- ✅ 远端对象存储：**Cloudflare R2**
- ✅ 不采用 GitHub 仓库图床（PicX）作为主存储（可作为未来可选增强，但当前不纳入范围）

## 3. 存储分层（概念）

### 3.1 结构化数据（DB）
- SQLite：旅行记录、POI、标签、花费拆分、附件元数据（Asset 表）等

### 3.2 非结构化数据（文件）
- 附件库：图片、PDF、Word、压缩包、票据扫描件等
- （可选）缩略图缓存：用于列表与抽屉快速预览

## 4. 附件库落盘规则（已确认）

> 目标：对人类可读、方便你手动整理；同时保证不重名、可备份、可迁移。

- ✅ 已确认：附件按 **城市 / 旅行** 目录结构存储。

推荐目录结构（草案）：

```text
APP_DATA_DIR/
├── db.sqlite
├── assets/
│   ├── cities/
│   │   └── 330100-杭州/
│   │       ├── city-cover/
│   │       │   └── {assetId}__hangzhou-cover.jpg
│   │       ├── trips/
│   │       │   └── 2026-04-04_2026-04-06-清明3日/
│   │       │       ├── photos/
│   │       │       │   ├── {assetId}__IMG_0001.jpg
│   │       │       │   └── {assetId}__IMG_0002.jpg
│   │       │       ├── docs/
│   │       │       │   └── {assetId}__行程单.pdf
│   │       │       └── receipts/
│   │       │           └── {assetId}__高铁票.jpg
│   │       └── poi/
│   │           └── 西湖/
│   │               └── {assetId}__sunset.jpg
└── thumbs/ (可选)
    └── ...
```

命名约定（推荐）：
- 文件名以 `{assetId}__原文件名.ext` 形式保存  
  - 好处：目录可读；且即使同名文件也不会冲突；assetId 方便从文件反查数据库记录

> 备注：目录名里的 `330100-杭州` / 日期范围等字段建议来自数据库（city_id、trip_id），避免你改名后导致路径失联。

## 5. Asset 元数据建议字段（补充）

Asset 表（建议）：
- `asset_id`
- `type`：image / pdf / doc / md / link / other
- `original_filename`
- `mime`
- `size`
- `sha256`（推荐，用于去重/校验/同步）
- `local_path`
- `remote_url`（可选；同步到 R2 后填）
- `created_at`

## 6. 导入/上传工作流（建议草案）

### 6.1 导入：选择文件/拖拽/粘贴 → 复制入库（必须）
1) 用户通过以下任一方式提供文件：
   - 文件选择器
   - 拖拽到“附件 Tab”
   - ✅ 已确认：在正文编辑器中 **粘贴/拖拽图片**
2) 应用计算 sha256（可异步）
3) 复制到附件库路径（以 asset_id 命名）
4) 写入 Asset 元数据（local_path 一定有）

插入到正文的链接规范（已确认）：
- ✅ 默认使用 `local://` 形式插入到 Markdown（离线优先）
- 渲染时：优先读取 local_path；若本地缺失且存在 remote_url，则回退使用 remote_url

插入时机（已确认）：
- ✅ 用户粘贴/拖拽图片后：先立刻在正文插入一个 `uploading...` 占位（不阻塞写作）
- ✅ 本地复制入库完成后：自动将占位替换为最终 `local://...` 链接
- （可选同步）上传到 R2 在后台进行，不影响正文插入

### 6.2 可选：上传到 Cloudflare R2（可配置）
1) 用户开启“同步到云端”
2) 后台队列上传（失败可重试）
3) 上传成功后写入 `remote_url`
4) 展示策略：优先 local_path，缺失再走 remote_url

## 7. Zip 全量导出规范（建议草案）

导出 zip 内容至少包含：

```text
backup.zip
├── manifest.json
├── db.sqlite
└── assets/
    └── ...
```

manifest.json（建议包含）：
- 导出时间、应用版本
- 数据库校验（hash）
- assets 列表（asset_id、sha256、relative_path、size、remote_url 可选）

## 8. 与“完全在线”的关系（第二阶段铺垫）

第二阶段上云时：
- SQLite 可迁移到服务端 DB（如 Postgres）或继续单用户 SQLite
- assets/ 可迁移到 R2（已有 remote_url 的可直接复用）
- 本机仍保留本地缓存，提升体验与离线能力
