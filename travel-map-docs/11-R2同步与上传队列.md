# 11｜R2 同步与上传队列（直连 R2）

> 目标：将本地产生的图片/附件可靠上传到 Cloudflare R2，以便备份与未来多端访问，并把 `remote_url` 写回 Asset 表。

## 1. 方案选择（已确认）

- ✅ 已确认：第一阶段采用 **客户端直连 R2（Client-Direct）**
  - 客户端本地保存 R2 Access Key / Secret Key（不进入前端 bundle，主进程读取）
  - 使用 S3 兼容 API（AWS SDK）上传与删除对象

> 备注：如果未来要发布给他人或做 Web 端，再升级为“Worker 签名 Presigned URL”的薄后端模式。

## 2. 同步队列与重试机制

### 2.1 触发时机（异步）
当本地文件写入成功且 SQLite 写入 Asset 成功后，将 `asset_id` 推入上传队列（Queue）。

### 2.2 并发控制
- 并发度建议：3~5（避免拥塞）

### 2.3 重试策略
- 默认不做复杂断点续传（单图通常 <10MB）
- 上传失败：标记为 pending 并重新入队（或下次启动继续）
- 建议记录：失败次数、最后失败时间、最后错误信息（便于 UI 提示）

### 2.4 写回策略
上传成功后：
- `UPDATE Asset SET remote_url = ? WHERE asset_id = ?`

## 3. 远端命名约定与动作

### 3.1 对象 Key（建议）
建议把对象 key 设计成“稳定且不需要重命名”的形式：
- 使用 `{assetId}__{original_filename}` 或 hash/uuid 前缀
- 避免未来改名导致远端迁移

### 3.2 删除一致性
当应用内触发 Asset 物理删除时（见《09》）：
1) 先删本地文件
2) 若存在远端对象：调用 SDK `deleteObject`
3) 最后删除 Asset 数据库记录

> 远端删除失败：记录日志并允许后续重试（不阻塞本地删除）。
